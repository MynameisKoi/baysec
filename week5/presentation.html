NETWORK ARCHITECTURE

Packets, Ports & Protocols

Understanding layer encapsulation and the mechanics of reliable connections.

🌐 4-LAYER PACKET ANATOMY
  • Layer 7 (Application): HTTP, DNS, SSH — The user data payload.
  • Layer 4 (Transport): TCP/UDP — Ports (80, 443, 8080), sequence numbers, reliability.
  • Layer 3 (Network): IPv4/IPv6 — Logical routing from Source IP to Destination IP.
  • Layer 2 (Data Link): Ethernet — Hardware MAC addresses for hop-by-hop local framing.
🤝 THE TCP 3-WAY HANDSHAKE

Before data flies, TCP establishes state between hosts:

1. SYN: Client ➔ Server: Let's talk (Seq=0)
2. SYN-ACK: Server ➔ Client: Ready (Seq=0, Ack=1)
3. ACK: Client ➔ Server: Connection established
4. PAYLOAD: Request flows (GET / POST)
💡 Every packet you capture is nested: Ethernet frames carry IP packets, which carry TCP segments, which carry HTTP.

HTTP VS HTTPS

The plaintext risk:

HTTP (80/8080) transmits raw tokens and passwords in plaintext.

HTTPS (443) encrypts payload via TLS.

⚠️ On shared Wi-Fi or compromised LANs, unencrypted HTTP leaks passwords and session cookies immediately to packet sniffers.

0x02 Solution: Dissecting the Uplink

Analyzing how unencrypted application telemetry reveals authorization secrets.

STEP 1: FILTER & IDENTIFY
  • Apply display filter: http or port 8080
  • Notice Packet #15: A POST /api/v2/telemetry/uplink request:
POST /api/v2/telemetry/uplink HTTP/1.1
Host: gateway.baysec.sfbu:8080
Authorization: Basic c2ZidV9hZG1pbj...==
Unlike encrypted TLS on 443, port 8080 was running unencrypted plaintext HTTP!
STEP 2: INSPECT PAYLOAD

HTML FORM URL ENCODED PAYLOAD:

station_id=SFBU-LAB-01&
operator_callsign=0xGhost&
auth_token=sfbu{w1r3sh4rk_p4ck3t_sn1ff3r_2026}
FLAG RECOVERED:
sfbu{w1r3sh4rk_p4ck3t_sn1ff3r_2026}
⚠️ KEY TAKEAWAY: Plaintext traffic over standard or non-standard ports (80, 8080) leaks credentials to any network tap.
